Approve

Clean, minimal, correct fix. The three substitutions are consistent with every other matview in the file, the replacement pipeline in syncPostgresMaterializedViews handles this matview, and production semantics are unchanged (NOW() = CURRENT_TIMESTAMP in PostgreSQL).

What this PR does

  • Replaces three instances of CURRENT_TIMESTAMP with the |||TIMENOW||| placeholder in the prow_job_runs_report_matview SQL definition in pkg/db/views.go.
  • This was the only matview still using CURRENT_TIMESTAMP directly; all others already used the placeholder.
  • In production, |||TIMENOW||| resolves to NOW(), so runtime behavior is unchanged.
  • With --pinned-time (seed data workflow), it resolves to a fixed timestamp, allowing the matview to return rows for seed data with past-dated timestamps.
  • Fixes a regression introduced in PR #3616, which added the 90-day time bound using CURRENT_TIMESTAMP instead of the established convention.
