Needs discussion — The expression index GORM tags on two new fields reference a column name that doesn't exist on their respective tables. This likely causes AutoMigrate failures or creates semantically wrong indexes. Should be confirmed and fixed before merge.

What this PR does

  • Adds ProwJobRelease to ProwJobRun, denormalizing the release from the parent ProwJob for future partitioning.
  • Adds ProwJobID, ProwJobRunRelease, and ProwJobRunTimestamp to ProwJobRunTest to support partitioning and eliminate a join needed to get variant data.
  • Adds ProwJobRunTestRelease and ProwJobRunTestTimestamp to ProwJobRunTestOutput for partitioning.
  • Updates the prow loader to thread release and timestamp through the full test-extraction pipeline.
  • Updates seed data and test fixtures to populate the new fields consistently.

Findings

Blocking Expression index tags reference nonexistent column

pkg/db/models/prow.go:96

ProwJobRunTimestamp time.Time `gorm:"expression:DATE(timestamp AT TIME ZONE 'UTC')"`

The expression references timestamp, which is a column on prow_job_runs, not on prow_job_run_tests. The actual column GORM will create for this field is prow_job_run_timestamp. This will either fail during AutoMigrate or create an expression index with wrong semantics. The same issue exists at line 120 for ProwJobRunTestOutput.ProwJobRunTestTimestamp.

Should fix Missing index on ProwJobRunTest.ProwJobID

pkg/db/models/prow.go:94

// skips joining on ProwJobRunID just to get ProwJobID
ProwJobID uint

The comment explains this field exists to avoid joins for variant lookups. If queries will filter or join on it, it needs gorm:"index". The adjacent ProwJobRunID has one. prow_job_run_tests is one of the largest tables; a missing index means full table scans.

Question No backfill for existing rows

pkg/db/models/prow.go:42-98

AutoMigrate adds these as nullable columns. All existing rows will have NULL values. For partitioning to work, these columns presumably need to be populated everywhere. Is the backfill planned as a separate migration or part of the partitioning work?

Nit PR description / code name mismatch

PR description says "ProwJobRunStartTime" but the field is actually ProwJobRunTimestamp.

Things I checked and found fine

  • The loader correctly threads prowJobRelease and pj.Status.StartTime through prowJobRunTestsFromGCS and extractTestCases.
  • Seed data populates all new fields with values consistent with the parent objects.
  • Test fixtures in job_runs_test.go and pr_new_tests_worker_test.go updated to include new required fields.
  • No existing queries are modified — purely additive schema change, low regression risk.
  • Hierarchical naming convention across tables (ProwJobRelease → ProwJobRunRelease → ProwJobRunTestRelease) is consistent and intentional for partitioning keys.

Open questions for the author

  • Have you tested that AutoMigrate succeeds with the expression index tags as written? The timestamp reference in the expression appears to target the wrong table's column.
  • Is the backfill for existing rows planned as a separate migration, or will it be part of the partitioning PR?
  • Should ProwJobRunTest.ProwJobID have an index tag given its stated purpose of avoiding joins?
