Verdict

Approve.

Documentation-only PR with no functional code changes. The feature doc is thorough, well-structured, and every code path and symbol reference it makes has been verified against the current codebase. The accompanying CodeRabbit and APM instruction changes create a reasonable maintenance feedback loop to keep the doc accurate as the feature evolves. One open question about GEMINI.md freshness.

What this PR does

  • Adds a comprehensive feature doc (docs/features/job-analysis-symptoms.md) covering the symptoms/labels system end-to-end: purpose, core concepts, data flow from definition through cloud-function detection to UI display, key code locations, API summary, and storage map.
  • Establishes a docs/features/ convention for feature documentation, with an APM instruction telling contributors to update feature docs alongside code changes.
  • Adds CodeRabbit path-specific review instructions for symptom-related code paths, prompting reviewers to suggest docs updates when those files change.
  • Adds a CodeRabbit "Feature Documentation" pre-merge check (warning mode) to nudge contributors toward keeping feature docs current.
  • Regenerates CLAUDE.md and AGENTS.md to pick up the new docs instruction.

Findings

Question GEMINI.md not regenerated

repo root

The APM source (.apm/instructions/docs.instructions.md) changed and both CLAUDE.md and AGENTS.md were regenerated, but GEMINI.md is absent from the diff. If it derives from the same APM source, make verify-apm may fail in CI.

Nit CodeRabbit brace-expansion glob may not match

.coderabbit.yaml:59

The path pkg/**/jobrun{scan,annotator}/** uses shell-style brace expansion. CodeRabbit uses minimatch/micromatch-style globs which do support braces, so this should work — but if it silently doesn't, the two paths would need separate entries.

- path: "pkg/**/jobrun{scan,annotator}/**"

Nit Parenthetical about JobRunAnnotator may go stale

docs/features/job-analysis-symptoms.md:128

The doc says JobRunAnnotator “can add labels but doesn't (yet) know about symptoms.” Accurate today, but the “(yet)” qualifier implies planned work that may or may not happen, making this line a staleness magnet. Consider stating the current state without the future-looking qualifier.

| `pkg/componentreadiness/jobrunannotator/jobrunannotator.go` | `JobRunAnnotator` - the `annotate-job-runs` tool which can add labels but doesn't (yet) know about symptoms. |
