Verdict

Request changes

The change itself is sound — correctly models Postgres template-DB semantics, preserves the existing testcontainers path as default, and mirrors the established scripts/e2e.sh pattern. The one thing to fix before merge is a documentation gap the project's own conventions call out explicitly: new env vars and Makefile targets should be reflected in .apm/instructions/. Everything else is a nit or a question for the author, not a blocker.

What this PR does

  • Adds ConnectToExternalPostgres() so test/integration can run against a Postgres instance provided via SIPPY_INTEGRATION_DSN, bypassing testcontainers-go (which needs a container runtime unavailable in CI test pods).
  • Fixes template-DB cleanup: unmarks IS_TEMPLATE before dropping, so the suite can be re-run repeatedly against the same Postgres instance without failing.
  • Adds scripts/integration.sh, modeled closely on the existing scripts/e2e.sh, handling devcontainer vs. bare-host setup and an early-exit fast path when the DSN is already provided by the caller.
  • Adds a make ci-integration target wrapping the new script.
  • Corresponding openshift/release CI wiring (Postgres sidecar + SIPPY_INTEGRATION_DSN) is described in the PR body as a follow-up, not part of this diff.

Things I checked and was fine with

  • PostgresContainer.Terminate nil-checks container correctly for the external-Postgres path; no nil-deref risk.
  • ALTER DATABASE ... IS_TEMPLATE = false before DROP DATABASE correctly models real Postgres semantics; errors from the ALTER are intentionally swallowed since the DB may not exist yet on a fresh instance.
  • scripts/integration.sh's caller-provided-DSN fast path bypasses devcontainer/host detection and calls make integration directly — correct for the CI sidecar case.
  • gofmt -l on both changed Go files reports no issues.
  • Unquoted shell variables ($DOCKER, $PSQL_CONTAINER, $PSQL_PORT) match the existing style in scripts/e2e.sh — consistent with convention, not a regression.
  • podman stop -i / podman rm -i is a legitimate podman flag (--ignore), used the same way in scripts/e2e.sh.
  • Test coverage: PR description states all 133 integration tests pass against both testcontainers and external-Postgres paths, plus the full unit suite — consistent with the project's "don't mock storage clients" convention, since the external-Postgres path can't reasonably be unit tested without a real DB.

Open questions for the author

  • Is the CI Postgres sidecar guaranteed to be one-per-job-pod, or could it ever be a shared/long-lived instance across concurrent PR checks? That changes whether the fixed template_integration name is safe.
  • Should scripts/e2e.sh adopt the same DSN password-masking (${DSN%%@*}@***) added here in scripts/integration.sh, for consistency in CI logs?
