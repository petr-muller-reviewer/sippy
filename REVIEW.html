Approve. Solid migration from BigQuery to PostgreSQL for the PR test results endpoint, with well-structured /payload sub-job transformation and good e2e coverage. Since the previous pass, the author resolved every should-fix from this review plus feedback from a human reviewer and CodeRabbit (magic-string constant, missing indexes/soft-delete guards, result limit, include_successes flake bug, latest_sha_only semantics). One should-fix remains (API docs), nothing blocking.

What this PR does

  • Detects /payload sub-jobs (via releaseJobName annotation) during BigQuery import and transforms them into presubmit-style records: stabilizes the job name by stripping the PR number, sets type to presubmit, routes to the Presubmits pseudorelease (now models.ReleasePresubmits).
  • Ports /api/pull_requests/test_results from BigQuery to PostgreSQL. Removes the BQ client dependency, changes response schema (status string replaces success/flaked booleans, output replaces failure_content).
  • Makes start_date/end_date optional (default: last 14 days), adds a latest_sha_only filter and a capped limit param, and removes the 30-day max range limit.
  • Adds synthetic presubmit seed data (seedPresubmitData) and comprehensive e2e tests for the endpoint, including a competing-SHA scenario for latest_sha_only.
  • Uses releaseJobName for variant identification on /payload jobs, overrides the release variant to the Presubmits pseudorelease, and suppresses TestGrid URL generation for these jobs.

Since previous review (d5763a01 → ee1291b15)

  • Introduced models.ReleasePresubmits constant and a ReleaseDefinition model with CapPullRequests, replacing hardcoded "Presubmits" strings across the codebase.
  • Added soft-delete guards, partition-aware JOIN conditions, and two new indexes (ProwPullRequest(org,repo,number), prow_job_run_prow_pull_requests(prow_pull_request_id)) addressing a human reviewer's performance findings.
  • Added a result limit (default/cap 10,000), fixed a follow-up crash where the limit param wasn't in the validation allowlist.
  • Fixed include_successes to exclude flakes, matching old BigQuery behavior.
  • Replaced the sha param with latest_sha_only, and updated seed data to link a second, older SHA so the filter is actually exercised by tests.
