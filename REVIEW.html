Verdict: Approve.

Small, well-scoped parity fix: the Postgres component-readiness provider gains the same IgnoreDisruption filter the BigQuery provider already applies, using the identical capability string. The change is a 4-line addition, builds cleanly, and is covered by a passing integration test. PR is merged.

What this PR does

  • Adds an IgnoreDisruption clause to buildDrilldownFilters in the Postgres data provider, appending AND NOT ('Disruption' = ANY(tow.capabilities)) to the outer clause when reqOptions.AdvancedOption.IgnoreDisruption is set.
  • Brings the Postgres provider to parity with the BigQuery provider, which already excludes tests carrying the Disruption capability under this option.
  • The clause is a literal string match against the ANY() array, so it needs no query placeholder/argument — outerArgs is left untouched.

Since previous review:

  • The original 135-line unit test file cr_queries_test.go was removed and replaced with a real-database integration test, TestIgnoreDisruptionFilter in test/integration/component_readiness_test.go (modeled after the existing TestCapabilitiesArrayOverlapFilter).
  • The new test seeds test ownerships with and without the Disruption capability and checks the filter's effect on QueryTestStatus results in three cases: filter on, filter off, and filter combined with an explicit capabilities filter.
  • PR merged at head 5c8df6287; approved by neisw, self-approved by openshift-trt-agent[bot], CI all-green.
