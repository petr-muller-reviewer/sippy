The four SQL fixes are real, well-reasoned, and now have solid regression coverage — particularly the row fan-out bug, which was the most consequential and easy to miss. Code quality is good and a prior nit was already addressed. The remaining blockers to a clean merge are process, not code: the stale-branch diff-size problem, unconfirmed CI container support, and an unaddressed (but low-severity) CodeRabbit nitpick.

What this PR does

  • Adds make integration: spins up a real Postgres container via testcontainers-go (with Podman auto-detection), runs SQL-level tests against it — a tier between unit tests (no DB) and full e2e.
  • test/integration/util/testdb.go / schema.go manage container lifecycle, per-test DB cloning (CREATE DATABASE ... TEMPLATE), and a hand-built integration schema (AutoMigrate models + the two custom SQL functions, skipping partitioning/matviews/triggers/GIN indexes).
  • test/integration/jobs_test.go has 21 tests: TestProwJobSimilarName (+LIKE-wildcard, case-sensitivity cases), TestVariantReports (+5 variants: multi-job, zero-previous-runs, empty variants, boundary timestamp, multi-release), TestJobReports (+5 variants: bugs, PRs, zero-previous-runs, filters/sort/limit, multi-release).
  • Fixes four real SQL bugs surfaced by these tests: a previous_failures/previous_fails column-name mismatch, boundary double-counting from symmetric BETWEEN windows, an open_bugs count that ignored the bug-status filter, and a row-fan-out bug where joining bugs/PRs into the main aggregation CTE inflated run/pass/fail counts.
Since the prior review (head 73738baf8): replaceDBName was rewritten to use net/url instead of manual byte-scanning (resolves a prior nit); a .PHONY: integration line was added; bugs #3 and #4 below and the associated TestJobReports_WithBugs / TestJobReports_WithPullRequests regression tests were added; test coverage roughly quadrupled (3 → 21 tests) via a runSpec/createRuns helper refactor.
