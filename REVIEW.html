What this PR does

  • Replaces payload_test_failures_14d_matview with a direct, partition-pruned SQL query (query.GetTestFailuresForPayloadStream) returning one pre-aggregated row per test (via array_agg) instead of one row per (test, job, payload) tuple.
  • Fixes two sort.Slice comparators that violated strict weak ordering (used >= instead of strict comparisons), adding deterministic tiebreakers (FailureCount, then Name).
  • Corrects the blocker-score reason string to say "not Rejected" instead of "Accepted", handling intermediate phases like "Ready".
  • Locks down /api/releases/test_failures to reject client-supplied sort params (400) since results are now pre-sorted server-side.
  • Updates scripts/rejected-payloads.py to a raw parameterized query mirroring the removed matview, and adds 36 new integration tests.

Things I checked and was fine with

  • Partition pruning: rt.release = ? + pjrt.prow_job_run_release = ? using the same literal is logically equivalent to the old column-to-column join, since both are pinned to the same value — correct and now prunable.
  • Dropping SELECT DISTINCT from the old matview is safe: release_job_runs has a unique index on prow_job_run_id enforced via ON CONFLICT (prow_job_run_id) DO UPDATE in the loader, so the duplicate-row risk the old TODO comment warned about cannot occur today.
  • sort.Slice comparators in both stream and single-payload paths were previously non-strict-weak-order (>=-based) — undefined behavior per Go's sort docs for equal elements. New tiebreaker chains fix this correctly.
  • array_agg(... ORDER BY pj.name, pjr.id) produces deterministic parallel arrays; per-release-tag sub-ordering by job name is preserved since the global sort key is a superset ordering. Confirmed by TestGetPayloadStreamTestFailures_MultipleJobsPerPayload.
  • filter.FilterableDBResult only calls .Order() when SortField is non-empty, so the new empty default sort field in jsonGetPayloadAnalysis doesn't leak an unintended default ordering.
  • gofmt -l and go vet are clean on all touched Go files.
  • Integration test coverage (36 tests) is thorough: window boundaries, stream/arch filtering, multi-payload aggregation, multi-job-per-payload arrays, blocker score + streak-override math, sort tiebreakers, openshift-tests exclusion, force-accepted-payload-with-failed-blocking-job edge case.
