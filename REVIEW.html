Verdict

Approve.

Two-line removal of dead SQL columns that were computed but never consumed. Verified via codebase-wide search that nothing references these columns. Safe, correct, and provides a measurable matview refresh speedup.

What this PR does

  • Removes two array_agg(tests.id) FILTER (...) expressions from the test_results CTE in jobRunsReportMatView.
  • The removed columns (failed_test_ids, flaked_test_ids) were computed inside the CTE but never selected by the outer query.
  • Eliminates unnecessary aggregation work during matview refresh (~19% speedup on staging).
  • No change to API surface — the JobRun struct never had fields for these ID arrays.

Findings

No findings. All review angles returned clean.

Things I checked and was fine with

  • failed_test_ids and flaked_test_ids are not referenced in the outer SELECT of the matview definition.
  • No Go struct (JobRun in pkg/apis/api/types.go) maps to these column names.
  • Codebase-wide grep (Go, SQL, TypeScript, JavaScript) finds zero references to either column.
  • SQL syntax after removal is correct — no dangling commas.
  • Matview auto-syncs via syncPostgresMaterializedViews hash comparison; no separate migration needed.
  • No BigQuery equivalent of this matview exists, so no parity concern.
  • API surface unchanged; no documentation update required.
