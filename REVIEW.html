Verdict Request changes

The change is a single line and directionally correct — it adds a new platform-detection entry in the right place in the ordered table — but the new pattern's matching semantics are inconsistent with every sibling entry (it requires a trailing dash where none of the others do), and there's no test covering it. Both are small, quick fixes.

What this PR does

  • Adds a new entry {"-gcd-", "gcd"} to the platformPatterns table inside setPlatform in pkg/variantregistry/ocp.go.
  • Placed correctly before the generic -gcp pattern so GCD jobs aren't misclassified as plain GCP.
  • Introduces the platform variant value gcd for OpenShift jobs running on Google's sovereign/dedicated cloud offering.
  • No other files touched — not the SQL job-name filters, not the test suite, not docs.

Findings

Should fix

should-fixPattern requires a trailing dash unlike every sibling entry

pkg/variantregistry/ocp.go:1145

{"-osd-ccs-gcp", "osd-gcp"},
{"-gcd-", "gcd"},
{"-gcp", "gcp"},

Matching is done via strings.Contains(jobNameLower, entry.substring) (line 1163). Every other pattern in this table (-gcp, -aws, -azure, -osd-ccs-gcp, ...) is a bare leading-dash substring that matches regardless of what follows. This new entry requires both a leading and trailing dash, so a job name ending in ...-gcd (no further suffix) would not match, silently falling through to "unable to determine platform" instead of classifying as gcd.

should-fixNo test coverage for the new pattern

pkg/variantregistry/ocp_test.go

job: "periodic-ci-openshift-release-master-nightly-4.19-e2e-osd-ccs-gcp",

TestVariantSyncer's table has a case for every other platform pattern (e.g. the osd-ccs-gcp case above, at line 279), but none was added for gcd. Without one, the trailing-dash issue above — or any future reordering of the pattern table — would go undetected.

Things I checked and was fine with

  • Placement in platformPatterns: correctly ordered before the generic -gcp entry, so GCD jobs won't be misclassified as plain GCP first.
  • Confirmed the matching mechanism (strings.Contains) by reading ocp.go:1163 directly.
  • Verified this really is a one-line diff by diffing against the true PR base (fda66a324) — no other files under pkg/variantregistry/ changed.

Open questions for the author

  • What do real GCD prow job names look like — does -gcd- ever appear as the final path segment (i.e. nothing after it but the end of the string)? If not, the trailing-dash requirement is harmless in practice, but it's still inconsistent with every sibling pattern here — worth confirming that's intentional rather than incidental.
