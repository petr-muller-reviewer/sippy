Verdict

Request changes

The toolchain migration itself (CRA/webpack → Vite, Jest → Vitest) is clean, mechanically verified (tests pass, build succeeds), and low-risk — but the final commit in the branch reverts three real security fixes (open redirect, ReDoS/crash, stored DOM XSS) under the mistaken premise that a .snyk exclude-path fix made the code changes unnecessary. It didn't — the exclude only suppresses the scanner. These need to be re-applied before merge.

What this PR does

  • Replaces react-scripts with Vite (dev server, build, preview) and Jest with Vitest.
  • 203 changed files, but 182 are pure .js→.jsx / .ts→.tsx renames with zero content change — the actual substantive diff is small.
  • Converts every process.env.REACT_APP_* reference to import.meta.env.VITE_* (verified complete via grep).
  • Removes Enzyme, PollyJS, and snapshot-testing infrastructure from setupTests, since (per PR description) no test used them.
  • Includes a security-fix commit for three Snyk-flagged issues, immediately followed by a revert commit that undoes the code fixes while keeping only the .snyk path corrections.

Findings

Blocking

Revert commit reintroduces open redirect, ReDoS/crash, and stored DOM XSS

sippy-ng/src/component_readiness/JobArtifactQuery.jsx, sippy-ng/src/prow_job_runs/IntervalsChart.jsx, sippy-ng/src/releases/ReleaseOverview.jsx (all reverted in commit c4cbe7a7a)

Commit c4cbe7a7a ("Revert security code changes, rely on .snyk excludes") frames itself as cleaning up churn caused by stale .snyk paths, but it actually reverts three real fixes from 8b910a33a. A .snyk exclude only suppresses the scanner finding — it does not fix the underlying vulnerability. All three bugs are live on the head SHA.

Nit

Single 7.5 MB JS bundle, no code splitting

sippy-ng/vite.config.js

npm run build on head SHA emits one index-*.js chunk at 7.5 MB (2.27 MB gzip), triggering Rollup's >500 KB chunk-size warning. Not a regression this PR needs to fix, but Vite makes build.rollupOptions.output.manualChunks / route-level dynamic import() easy to add as a follow-up.

Nit

esbuild surfaces pre-existing dead code during build

sippy-ng/src/helpers.jsx, sippy-ng/src/jobs/JobAnalysis.jsx

Build warns Comparison using the "===" operator here is always false for filter.items === [] (array-literal reference comparison, always false). Pre-existing bug, out of scope here, but now visible for free via Vite's esbuild step where CRA's pipeline didn't surface it. Worth a follow-up ticket.

Nit

README drops documented API-component test convention with no replacement

sippy-ng/README.md

The rewrite removes the old convention text ("components hitting the API should have a snapshot + canary text + call-count test") along with the now-defunct PollyJS/snapshot workflow instructions. Justified given Vitest+RTL don't use that flow, but nothing replaces the underlying convention guidance.
