Verdict

Approve
Config-only change that faithfully replicates the established qe-auto-release pattern for OCP 4.22. No correctness or behavioral issues found. One cosmetic ordering nit noted below.

What this PR does

  • Adds a single new entry 4.22-qe-auto-release to config/qe-views.yaml.
  • The view compares the current 7-day window (now-7d → now) against the 30-day pre-GA baseline (ga-30d → ga) for OCP 4.22.
  • Scoped to the automated-release procedure, QE/service-delivery-owned jobs, and standard platforms (aws, azure, gcp, rosa, vsphere).
  • No Go code changes; the YAML file is consumed at runtime via CLI flag.

Findings

Nits

nit 4.22 entries appear after 5.0 entries, breaking chronological order
config/qe-views.yaml:983

All prior releases (4.14–4.21) are ordered with lower release numbers before higher ones. The new 4.22 entries were appended at the end of the file, after 5.0-qe-main (line 873) and 5.0-qe-auto-release (line 927). No runtime impact — the list is not order-sensitive — but it breaks the file's readability convention. 

...5.0-qe-auto-release  (line 927)
  - name: 4.22-qe-auto-release  ← new, appended after 5.0
    ...
  - name: 4.22-qe-main          ← also after 5.0

Consider inserting the 4.22 pair before the 5.0 entries.

Things I checked and was fine with

  • base_release.release: "4.22" with ga-30d/ga — correct, same-release baseline is the established pattern for all prior qe-auto-release views.
  • sample_release using now-7d/now — correct for an auto-release view monitoring current state.
  • Upgrade in db_group_by but absent from include_variants — intentional; absence means "don't filter on this dimension," so all Upgrade values pass through and are grouped for display. Universal across all qe-auto-release entries.
  • Procedure: automated-release — recognized variant value in pkg/variantregistry/ocp.go.
  • ignore_disruption: true — standard for all qe-auto-release views.
  • No Go code has hardcoded view name lists; the file is consumed via CLI flag, so no secondary changes needed.
  • validateViews in component_readiness.go only checks variant_cross_compare vs db_group_by conflicts; this entry has no variant_cross_compare, so it passes cleanly.
  • Platforms, installers, networks, topologies, and advanced options match the 4.21-qe-auto-release entry exactly.

Open questions for the author

  • Should the 4.22 entries be reordered to appear before the 5.0-* entries to restore chronological ordering in the file?
