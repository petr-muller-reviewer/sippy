Verdict: Request changes

Both JS bugfixes are correct and well-targeted, and the Postgres capability-filter addition is verified correct and consistent with BigQuery parity. But the fix for the actual reported bug (test_filters not syncing from the selected view) has zero automated test coverage — only manual browser verification is claimed in the PR description. Given the severity of the regression this bug caused (86 → 400+ spurious results), I'd want at least a targeted unit test before merging.

What this PR does

  • Fixes updateVarsFromView() in CompReadyVars.jsx to sync test_filters (lifecycles, capabilities) from the selected view into React state — previously this was silently dropped, causing the sample query to lose its lifecycle filter and inflate regression counts.
  • Fixes a state-mutation bug in replaceIncludeVariantsCheckedItems/replaceCompareVariantsCheckedItems, which mutated state objects directly before calling their setters — invisible to React's reference-equality change detection.
  • Switches compareVariantsCheckedItems from useState([]) (an array used as an ad-hoc map) to useState({}), consistent with the sibling state.
  • Extends buildDrilldownFilters in the Postgres query layer (cr_queries.go) to apply a top-level reqOptions.Capabilities array-overlap filter, matching BigQuery's existing behavior.
  • Adds a synthetic Azure job/test to seed data, outside the default view's variant filter, to exercise variant exclusion.
