Verdict

Request changes — one confirmed job silently dropped from all views; one open question about coverage. The PR's intent (separating integration FVT jobs from rosa-stage) is correct, but the positive-enumeration approach misses at least one production FVT job that was previously tracked. Worth a quick fix before merging.

What this PR does

  • Replaces the broad catch-all ^periodic-ci-openshift-online-rosa-e2e-main-.* in rosa-stage with three specific patterns: nightly (periodics-*), upgrade (upgrade-*), and OCM FVT staging (ocm-fvt-*-staging-*).
  • Adds a new pattern for SRE operator e2e staging jobs to rosa-stage: ^periodic-ci-openshift-.*-master-rosa-sts-e2e-promotion-stage$.
  • Populates the previously-empty rosa-integration view with OCM FVT integration and SRE operator integration job patterns.
  • Fixes incorrect placement of 9 integration FVT jobs that the old catch-all was routing into rosa-stage.

Findings

should fix ocm-fvt production job dropped from all views
config/openshift-customizations.yaml:72

The job periodic-ci-openshift-online-rosa-e2e-main-ocm-fvt-rosa-hcp-production-ocm-fvt-periodic-cs-rosa-hcp-ad-production-main exists in config/openshift.yaml and was previously matched by the old catch-all. The new patterns cover *-staging-* (rosa-stage) and *-integration-* (rosa-integration), but there is no pattern for *-production-*. After this PR, that job matches no view and disappears from all dashboards silently.

Fix: Either add a ^periodic-ci-openshift-online-rosa-e2e-main-ocm-fvt-.*-production-.* pattern to rosa-stage (if staging OCM manages production), or to rosa-production (if it should be tracked there).
question Daily CI status bot mentioned but not covered
config/openshift-customizations.yaml:68

The PR description lists "Daily CI status bot" as a job category that should remain in rosa-stage. None of the three new rosa-e2e-main-* patterns (periodics-*, upgrade-*, ocm-fvt-*-staging-*) would match a daily-status-type job unless it happens to start with periodics-. If this job exists and uses a different prefix, it is now untracked.

Things I checked and was fine with

  • -master- branch in operator patterns: verified against config/openshift.yaml — the actual job is periodic-ci-openshift-route-monitor-operator-master-rosa-sts-e2e-promotion-stage. The route-monitor-operator repo uses master, so the pattern is correct.
  • Removing jobs: {} from rosa-integration: Go nil-map reads and range loops are safe; all callers in pkg/variantregistry/ handle nil maps correctly. No panic risk.
  • rosa-integration database registration: the release was introduced as a registered placeholder in a prior commit; the CLAUDE.md TRT-ticket requirement applies to creating new releases, not populating existing placeholders.
  • Pattern structure and conventions: regexp-only sections without a jobs: key are consistent with Presubmits and ocp-hypershift. The stage/integration pairing follows the ARO convention.
