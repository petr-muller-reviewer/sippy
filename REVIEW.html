Verdict

Approve

Targeted, correct fix for a real regression. The statusCapturingResponseWriter introduced in 160d54da wraps http.ResponseWriter without implementing http.Hijacker, which breaks gorilla/websocket's upgrade handshake on /api/chat/stream. The added Hijack() delegation and regression test are well-scoped and clean.

What this PR does

  • Adds a Hijack() method to statusCapturingResponseWriter that delegates to the underlying writer's http.Hijacker implementation.
  • Returns a clear error if the underlying writer doesn't support hijacking.
  • Adds a test that performs a real WebSocket upgrade through the logRequestHandler middleware, verifying the full round-trip including the 101 status code.
  • Fixes the /api/chat/stream endpoint which was broken by the logging middleware introduced in 160d54da.

Findings

nit Logged status is 200 for hijacked WebSocket connections

pkg/sippyserver/server.go:2963-2969

After a successful Hijack(), WriteHeader(101) is never called on the wrapper — sw.status stays at the default http.StatusOK. The log line will report status: 200 for successful WebSocket upgrades. Cosmetically misleading but functionally harmless. 

sw := &statusCapturingResponseWriter{ResponseWriter: w, status: http.StatusOK}
start := time.Now()
h.ServeHTTP(sw, r)
log.WithFields(log.Fields{
    "status": sw.status,
}).Info("responded to request")

nit Other optional ResponseWriter interfaces not delegated

pkg/sippyserver/server.go:2935-2951

The wrapper also doesn't implement http.Flusher (needed for SSE/chunked responses) or http.Pusher. Only Hijacker is needed right now for the WebSocket path, so this is correct scope. If SSE endpoints are added later, Flush() delegation would be needed too. No action required now.

Things I checked and was fine with

  • Hijack() correctly type-asserts the underlying writer and returns a clear error when it doesn't implement http.Hijacker.
  • Comment on the method explains why (the specific endpoint), not just what.
  • Test uses httptest.NewServer with a real gorilla upgrader, verifying the full round-trip.
  • Import additions (bufio, net, gorilla/websocket) are all necessary and minimal.
  • Root cause identification (commit 160d54da) is correct.

Open questions for the author

  • Would it be worth logging status: 101 explicitly when a hijack occurs, so WebSocket upgrades are visible in request logs? Minor, not blocking.
